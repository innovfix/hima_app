Blocker Bugs (5) - Cannot release with these

BUG-001: When the host leaves, other users stay stuck inside the room forever

Blocker
Screen / Feature
IPL Room Call Screen
Perspective
FunctionalReal-User
Steps to Reproduce
  1. Female user creates an IPL room and enters the call screen
  2. Male user joins the same room
  3. Host (female) taps the Leave button and confirms "Close Room"
  4. Observe the male user's screen
Expected Result
The male user should see a message like "Host ended the room" and be taken back to the home screen automatically.
Actual Result
Nothing happens on the male user's screen. They stay inside the room with no indication that the host left. The room appears to still be active. The only way out is to manually tap Leave or force-close the app.
Frequency
Always (tested 3 times)
Extra Notes
This also means the user's coins keep getting deducted even though the room is effectively dead. Users will lose money on a dead session.

BUG-002: Minimizing the app drains battery fast - audio and timer keep running in the background

Blocker
Screen / Feature
IPL Room Call Screen
Perspective
Real-UserUX
Steps to Reproduce
  1. Join an IPL room as a male user
  2. Press the Home button to minimize the app
  3. Wait 5 minutes
  4. Check battery usage and re-open the app
Expected Result
Audio should pause when the app is minimized. The timer should pause or the app should show a notification that the session is still active. Battery usage should be minimal.
Actual Result
The audio keeps streaming in the background, the countdown timer keeps running, and the screen stays awake even though the app is minimized. Battery drops noticeably. The user is also shown as "talking" to other members even though they're not using the app.
Frequency
Always

BUG-003: People in the room don't see when someone joins, leaves, or when the room closes

Blocker
Screen / Feature
IPL Room Call Screen
Perspective
FunctionalReal-User
Steps to Reproduce
  1. Two users join the same IPL room
  2. A third user joins the room
  3. Observe the first two users' screens
Expected Result
The participant slots should update to show the new member. Similarly, when someone leaves, their slot should become empty.
Actual Result
The participant list only loads once when you first enter the room. After that, it never updates. If someone joins or leaves after you're already inside, you don't see the change until you exit and re-enter the room. The room feels frozen.
Frequency
Always

BUG-004: Users with not enough coins can still join a room

Blocker
Screen / Feature
Join Room (Random) flow
Perspective
Functional
Steps to Reproduce
  1. Log in as a male user who has only 40 coins (the minimum required is 60)
  2. Tap the IPL Rooms button on the home screen
  3. Select a team and tap "Join Randomly"
Expected Result
The app should show a message like "You need at least 60 coins to join a room" and prevent the user from entering.
Actual Result
The user successfully enters the room even though they don't have enough coins. The timer shows a shorter time, and the user's coins will go negative or the settlement will fail when they leave.
Frequency
Always (verified via API testing)

BUG-005: Rotating the phone disconnects you from the call and resets everything

Blocker
Screen / Feature
IPL Room Call Screen
Perspective
Real-User
Steps to Reproduce
  1. Join an IPL room
  2. Rotate the phone from portrait to landscape
Expected Result
The screen should either stay in portrait mode (locked) or adjust to landscape without losing the audio connection, timer, or participant list.
Actual Result
The entire screen reloads. The audio connection drops, the countdown timer resets to zero, and the participant list goes empty. The user is effectively disconnected from the room but the server still thinks they're inside (coins still being charged).
Frequency
Always

Critical Bugs (6) - Major features broken

BUG-006: The countdown timer shows the wrong remaining time

Critical
Screen / Feature
IPL Room Call Screen (Male user timer)
Perspective
Functional
Steps to Reproduce
  1. Log in as a male user with 40 coins (at 10 coins per minute, should get 4 minutes)
  2. Join an IPL room
  3. Look at the countdown timer at the top of the screen
Expected Result
Timer should show approximately 4:00 (40 coins / 10 per minute).
Actual Result
Timer shows 2:00 and the system reports only 20 coins. Half the user's balance is missing or miscalculated. The user gets kicked out earlier than expected.
Frequency
Always (verified via API)

BUG-007: When the internet drops or is slow, the app just keeps loading forever with no message

Critical
Screen / Feature
Room List Screen / Call Screen
Perspective
Real-UserUX
Steps to Reproduce
  1. Turn on Airplane mode or switch to very slow network
  2. Open the IPL Rooms list
  3. Or try to join a room
Expected Result
A clear message like "No internet connection" should appear with a "Try Again" button.
Actual Result
The screen stays blank with no loading circle, no error message, and no retry option. The user has no idea if the app is loading or broken. The only option is to close and reopen the app.
Frequency
Always

BUG-011: Sensitive login information is being recorded in system logs

Critical
Screen / Feature
All screens (background process)
Perspective
Real-User
This is a security concern flagged privately for developers. The user's login credentials are being written to the phone's system logs in plain text. Any other app with log-reading permission could steal the user's account. This should be removed immediately before any public release.

Major
Screen / Feature
IPL Room Call Screen - Reaction buttons (FOUR, SIX, WICKET, GREAT)
Perspective
UXFunctional
Steps to Reproduce
  1. Join an IPL room
  2. Tap any reaction button (e.g. FOUR) very quickly 5-6 times
Expected Result
Only one reaction should register per tap, with a short cooldown between taps.

All 5-6 taps register. Multiple floating animations play simultaneously and multiple reactions are sent. Could look spammy to other users.

BUG-021: The screen reader does not read out what the reaction icons mean

Minor
Screen / Feature
IPL Room Call Screen - Reaction area
Perspective
Real-User
Actual Result
A visually impaired user using TalkBack cannot tell what the reaction buttons do because they don't have readable labels. The screen reader just says "button" without describing which reaction it is.

BUG-022: The speaking glow around a user's avatar is the only way to tell who is talking

Minor
Screen / Feature
IPL Room Call Screen - Participant slots
Perspective
UI
Actual Result
The only way to tell who is speaking is a green glow around their avatar. There is no text label like "Speaking" or a small microphone icon animation. Users who are color-blind may not notice the glow.

BUG-023: Long room names get cut off with "..." and there's no way to see the full name

Minor
Screen / Feature
IPL Rooms List - Room cards
Perspective
UI
Actual Result
Room names longer than one line get cut off with "..." at the end. There's no tooltip, long-press popup, or second line to show the full name. Users can't tell rooms apart if names are similar.

BUG-024: The mute and speaker buttons don't clearly show their current state

Minor
Screen / Feature
IPL Room Call Screen - Control buttons
Perspective
UX
Actual Result
The only visual difference between muted and unmuted is a slight transparency change. There's no color change, no crossed-out icon, and no label text. It's easy to forget whether you're muted or not.

BUG-025: Right-to-left languages (like Arabic) don't display correctly

Minor
Screen / Feature
All IPL Room screens

When the device language is set to Arabic or Hebrew, the layout does not mirror. Buttons and text stay left-aligned instead of flipping to right-to-left. The flow feels broken for RTL language users.

Release Verdict: NOT READY

5 Blocker bugs must be fixed before any release. The core feature of hosting a room is broken (host leave not detected), the app drains battery in background, phone rotation kills the session, and users can join without enough coins.

Next Steps: Fix all 5 blockers + 6 critical bugs. Then run a quick smoke test on 2 devices. Then re-evaluate for release.
