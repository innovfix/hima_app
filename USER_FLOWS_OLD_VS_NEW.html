Hima — User Experience Flows

How the app behaves for New Users vs Old Users, plus the temporary Profile switch.

Product Reference · Internal

Overview

Hima treats users in two distinct ways. A New User is someone who has never paid for talktime and is offered a one-time trial subscription. An Old User is a returning user who already has a wallet balance and is charged per minute for calls. The app decides which flow to show at every screen — the home coin balance, the call buttons, and the recharge sheets all behave differently.

What the user sees New User Old User
Coin balance on Home Always shown as 0 Actual wallet balance
Tap on coin balance Opens the Trial Offer sheet Opens the full Wallet screen
Tap on Audio / Video call Opens the Trial Offer sheet If balance is enough → call starts.
If not → Insufficient Funds sheet opens.
Primary call-to-action “Try Now” → one-time subscription “Add Coins” → recharge in place, or subscribe for unlimited calls

The two flows, side by side

Each card walks through what a user sees and does, from opening the app to reaching a call.

New User Flow Trial path

A first-time user who has not yet subscribed.
  1. Lands on Home. The coin badge shows 0 even if the server returned a balance, because a new user hasn’t made a real purchase yet.
  2. Taps the coin badge. The Trial Offer bottom sheet opens, explaining the one-time offer and benefits.
  3. Taps an Audio or Video call button on a profile. Instead of starting a call, the same Trial Offer sheet opens — the user must subscribe before they can call.
  4. Taps “Try Now”. The app opens the subscription screen where the user completes the one-time purchase. After purchase, the user is treated as an active subscriber.
  5. After subscription. The user can now start calls directly. The trial sheet no longer appears.

Old User Flow Recharge path

A returning user who pays per minute from their wallet.
  1. Lands on Home. The coin badge shows the user’s actual wallet balance from the server.
  2. Taps the coin badge. The full Wallet screen opens, where the user can see transactions and recharge directly.
  3. Taps an Audio or Video call button on a profile. The app checks whether the balance covers at least one minute at that creator’s per-minute rate. If enough → call starts If not → sheet opens
  4. Insufficient Funds sheet opens. The sheet shows:
    • A title explaining the balance is too low to make the call.
    • A yellow Subscribe Now banner with unlimited chats, ₹399 talktime, one free call daily.
    • A Talktime Recharge grid identical to the Wallet screen’s coin packs.
    • An Add Coins button at the bottom.
  5. Taps “Add Coins”. Payment starts right inside the sheet — no redirect to the Wallet screen. The user completes payment through the existing gateways (UPI / card / etc.) and returns to the app.
  6. Alternatively, taps the yellow Subscribe banner. The subscription screen opens so the user can switch to unlimited calls instead of one-time recharge.

How the app decides what to show on a call tap

A simple three-way check runs every time an audio or video call button is tapped.

User type Condition What happens
New User Not yet subscribed Trial Offer sheet subscribe to continue
New User Subscription active Call starts directly
Old User Wallet balance covers the rate Call starts directly no sheet
Old User Wallet balance is below the rate Insufficient Funds sheet recharge required

Profile switch (temporary)

While the backend does not yet return a reliable “new vs old” flag for every user, the Profile screen includes a developer switch that lets the team flip any account between the two flows for testing.

How it is used today

  1. Open Profile. A toggle labelled “New User Mode” is visible in the developer section of the screen.
  2. Turn it ON. The app behaves as if the signed-in account is a brand-new user — coin balance shows 0, and every call tap opens the Trial Offer sheet.
  3. Turn it OFF. The app falls back to the normal Old User behaviour — real wallet balance, Wallet screen, and the Insufficient Funds sheet when balance runs out.
📸 Screenshots to include 1. Profile screen with the switch OFF (Old User)  ·  2. Profile screen with the switch ON (New User)
To be removed after backend work Once the backend starts returning a definitive signal for each account (whether the user is a new user or a returning user with wallet history), this manual switch will be removed from the Profile screen. The two flows themselves stay — only the toggle goes away. From that point on the app will decide the flow automatically from the server response, and QA will no longer need to flip it by hand.

Quick summary

  • New User — always shown trial offer, one-time subscription unlocks calling.
  • Old User — wallet-based, calls start if balance is enough, recharge sheet appears when it’s not.
  • Recharge happens in place — the sheet completes payment without sending the user to the Wallet screen.
  • Subscribe banner is always present in the old-user sheet as an upsell to unlimited calls.
  • Profile switch is a temporary tool for QA and will be removed once the backend provides the flag.
