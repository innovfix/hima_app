2. Testing Performed

2.1 API Testing

Black-box API testing against the dev backend (https://demohima.himaapp.in/api/auth) using a Python test harness that drives urllib directly — independent of the Android client. Positive, validation, security, boundary and performance cases per endpoint.

  • Exercised 5 endpoints: /user_validations, /avatar_list, /update_profile, /speech_text, /update_voice.
  • Confirmed IDOR on three mutating endpoints: /user_validations, /update_profile, /update_voice all accept a foreign user_id in the request body instead of deriving it from the JWT subject (BUG-EP-005, BUG-EP-010, BUG-VV-006). The /update_voice IDOR was proven with a real overwrite of another user's voice recording.
  • Confirmed /avatar_list and /speech_text are reachable without authentication at all (BUG-EP-008, BUG-VV-002).
  • Confirmed /update_profile crashes to HTTP 500 HTML on the second name change and on 30-interest payloads, instead of returning JSON errors (BUG-EP-015, BUG-EP-013).
  • Confirmed /update_profile accepts missing name field — blanks out the display name (BUG-EP-012).
  • Confirmed /update_voice accepts a 10 MB file with no size or MIME cap server-side (BUG-VV-008); server does reject WAV in favour of MP3 (VV-UV-11 positive case).
  • Total cases executed: 42. Artifacts: QA_Reports/automation/edit_profile_voice_api_tests.py (source, reproducible) and QA_Reports/automation/Hima_EditProfile_Voice_API_Report.pdf.

2.2 UI Automation Testing

Scripted UI automation driven via adb shell input and uiautomator dump, plus a deterministic static analyser parsing the layout XML and activity Kotlin source for standard Android UX and performance anti-patterns.

  • Voice Verification (live UI on emulator-5554): 10 test cases — all PASS. Verified the new 30-second auto-stop fix works on device by holding the mic button past the cap (V-06), verified rapid-tap resilience (V-07), and verified graceful handling under airplane mode (V-10).
  • Edit Profile (static UI + code analysis): 12 checks covering maxLength, inputType, accessibility labels, button-disabled-while-loading, text-watcher debouncing, SharedPreferences reads on scroll, unsaved-edits guard, Html.fromHtml on name fields, interests cap, and observer wiring. Initial run surfaced 5 failures (E-04, E-05, E-06, E-07, E-08). All 5 fixed in the same session; re-run shows 12/12 PASS.
  • Why static for Edit Profile: the test account (mobile 9876543210) fell into the terminal “Almost done — under review” state for female creators during API testing, blocking navigation to the home screen. Static analysis caught the same category of issues a live Espresso pass would.
  • Total automated cases: 22. Artifacts: QA_Reports/ui_automation/run_voice_tests.py, QA_Reports/ui_automation/run_edit_profile_static.py, QA_Reports/ui_automation/Hima_UI_Automation_Report.pdf.

4. Client-Side Changes Landed Today

4.1 Voice Verification — 30-second auto-stop (Fully fixed)

  • Reduced CountDownTimer window from 1 hour (60 * 60000 ms) to 30 seconds in BottomSheetVoiceIdentification.kt.
  • Implemented onFinish() (previously empty) so the recording auto-stops, shows a “Max 30 seconds” toast, clears the ripple animation, and routes through the existing stopRecording(false) path so the Submit / Play / Re-record buttons appear exactly as they would on a normal release.
  • Verified on device (V-06) and on emulator: a 32-second press auto-stops at 30 s and the review UI appears.

4.2 Voice Upload — explicit MIME + 5 MB client guard (Partially fixed)

  • VoiceIdentificationActivity.kt now passes asRequestBody("audio/mpeg".toMediaTypeOrNull()) so the server receives the correct Content-Type header instead of the previous empty / octet-stream default.
  • Client rejects any recording above 5 MB with a user-facing toast (“Recording too large, please re-record”) and deletes the file to reclaim storage.
  • Null / zero-byte files are also rejected before the upload call.

Backend still required: the server currently accepts a 10 MB payload (BUG-VV-008). Server must enforce 'voice' => 'file|mimes:mp3|max:10240' plus an nginx client_max_body_size guard — curl users bypass any client cap.

4.3 Edit Profile — 5 UI fixes in a single activity (Fully fixed)

  • E-04: added android:contentDescription="@string/back" and clickable/focusable=true on cv_back; moved accessibility responsibility off the inner iv_back ImageView. TalkBack now announces “Back, button” instead of “Unlabeled button”.
  • E-05: binding.btnUpdate.isEnabled = false added at the moment the loader appears; re-enabled in both the success and error observer paths. Double-tapping the Update button no longer fires two /update_profile calls.
  • E-06: name validation now uses Handler.postDelayed with a 300 ms debounce and removeCallbacks on each keystroke. Typing "Aravindan" fires exactly one call to /user_validations instead of nine.
  • E-07: cached originalUserName, originalAvatarId, originalInterestsList, and cachedUserId in onCreate(). Removed the getPrefs().getUserData() call from updateButton() so no SharedPreferences read happens on every avatar scroll tick.
  • E-08: both the back icon (cv_back) and the system back key (onBackPressedDispatcher) now check hasUnsavedChanges() and show an AlertDialog (“Discard / Keep editing”) when the user has modified the name, avatar, or interests. Added 3 strings to strings.xml.
  • Added onDestroy() to remove any pending debounce runnable, avoiding a handler leak.

4.4 Edit Profile — UI-BUG-001 HTML-in-toast sanitizer (Partially fixed)

  • Added a private helper safeServerMessage(raw: String?) in EditProfileActivity.kt. It returns the generic “Please try again later” fallback whenever the server's response message starts with <, contains <!doctype / <html / <body, mentions “stack trace” or “exception in”, or exceeds 160 characters.
  • Wired in 3 places: the name-validation success-false observer (toast + hint TextView), the name-validation error observer, and the update-profile failure toast.
  • Logcat during manual re-test confirmed the sanitizer is working: “userValidationLiveData received: success=false, message=<!DOCTYPE html>...” is followed by “Displaying error message: Please try again later” on the very next line.

Backend still required: the server should never return HTML to an API route. Laravel's exception handler must return {"success":false,"message":"..."} JSON for every throwable on api/* routes (tracked as BUG-EP-017).

5. Documented-Only Bugs (backend fix required)

These bugs have no meaningful client-side mitigation — the root cause is on the server. They are captured in the API test report with repro steps, proofs, and recommended fixes for the backend team.

  • BUG-EP-005 — /user_validations: derive user id from JWT sub; stop trusting body user_id.
  • BUG-EP-008 — move /avatar_list behind the auth:api middleware group.
  • BUG-EP-010 — /update_profile: same IDOR fix pattern; use $request->user()->id, never body user_id.
  • BUG-EP-012 — add FormRequest 'name' => 'required|string|min:4|max:10'; return JSON 400 instead of silently accepting empty.
  • BUG-EP-013 — add 'interests' => 'array|max:5|in:Politics,Art,...' so the server enforces what the UI already limits to 5.
  • BUG-EP-015 — the “change name only once” rule currently throws an uncaught exception on the second call. Wrap in a validator / try-catch and return JSON {"success":false,"message":"You can change your name only once."}.
  • BUG-EP-017 — /user_validations returns HTML 500 for user_id=456976 (reproducible on our test mobile). Fix the underlying exception and ensure the exception handler returns JSON on api/* routes.
  • BUG-EP-018 — add Laravel throttle:30,1 middleware on /user_validations; 7 crashing requests in 20 s all hit the server with no back-off.
  • BUG-VV-002 — /speech_text must require JWT; voice prompts are currently scrapable without auth.
  • BUG-VV-006 — /update_voice IDOR: same fix pattern. Voice is the gating step for female creator verification, so this is account-takeover-adjacent.
