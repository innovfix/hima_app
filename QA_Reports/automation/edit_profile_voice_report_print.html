2. Who needs to fix what

Every failure was classified by where the fix actually closes the hole. A fix belongs to the server if a curl-wielding attacker would bypass any client-side guard.

Android only
0
  • No bug is purely client-fixable — the app is well-behaved.
Android + Backend
1
  • Voice upload size cap — client should limit recording duration; backend must enforce byte cap.
Backend only
9
  • Fix IDOR on /update_profile, /update_voice, /user_validations — use JWT sub, not body user_id.
  • Add auth middleware on /avatar_list, /speech_text.
  • Replace HTTP 500 crashes with JSON error responses.
  • Add FormRequest validators (name, interests, file size).

Bottom line: 10 of 10 bugs need backend work. 0 can be closed by Android alone.

3. Bugs — plain-language breakdown

CRITICAL BUG-EP-005 FIX: SERVER Edit Profile

/user_validations — IDOR: validate another user's id

What's wrongAnyone logged in can validate a name as if they were a different user.
Why it mattersLets an attacker probe which user IDs exist and what names are taken on other accounts.
How to fixBackend: take the user_id from the login token, ignore the one sent in the request body.
Server response observed{"success":true,"message":"Name is valid."}
MEDIUM BUG-EP-008 FIX: SERVER Edit Profile

/avatar_list — no auth header

What's wrongThe avatar list API works without a login token at all.
Why it mattersLow severity, but any scraper can pull the whole avatar catalogue without signing in. Reduces attack surface to have one consistent auth policy.
How to fixBackend: put this route behind the same auth middleware as the rest.

CRITICAL BUG-EP-015 FIX: SERVER Edit Profile

/update_profile — happy path (clean name + 1 interest)

What's wrongUpdate-profile is crashing with HTTP 500 'Server Error' (plain Laravel error page) instead of returning a clean JSON error.
Why it mattersCritical for UX: the app shows the generic 'please try again later' toast instead of the real reason (e.g. 'you can change your name only once'). Also leaks the framework identity to anyone probing the API.

CRITICAL BUG-EP-010 FIX: SERVER Edit Profile

/update_profile — IDOR: update foreign user_id

What's wrongA logged-in user can overwrite another user's profile (name, avatar, interests) by sending a different user_id.
Why it mattersCRITICAL. This is close to account takeover — attacker can wipe, impersonate or defame any user with a single API call.
How to fixBackend: derive user_id from the login token, not from the request body. Apply to every endpoint that takes user_id.
Source refapp/src/main/java/com/gmwapp/hima/activities/EditProfileActivity.kt:241

MEDIUM BUG-VV-008 FIX: BOTH Voice Verification

/update_voice — 10 MB file (mime/size guard)

What's wrongThe server accepts a 10 MB upload on /update_voice — no size limit observed.
Why it mattersMedium. Storage-DoS risk — an attacker can upload gigabytes of junk over time and inflate S3 bills.

5. Methodology

  • Tests authenticated with a real JWT obtained via /login for QA mobile 9876543210.
  • IDOR tests use user_id − 1 to stay within valid DB range while probing cross-user access.
  • Voice tests use synthesised silent MP3 / WAV fixtures — no real user voice recorded.
  • Each request includes 200 ms spacing to avoid triggering throttle middleware.
  • Profile mutated during the suite is restored to its original state at the end.
