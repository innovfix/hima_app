4. Edit Profile — note on live testing

Why I couldn't run live UI tests on Edit Profile this session:

The test account (mobile 9876543210) is currently stuck on the "Almost done… Your profile is under review" screen. This is a terminal state for female creators waiting for manual approval — there's no navigation away from it. Because of that, the Edit Profile activity was not reachable on the emulator.

To still produce useful test results for the Edit Profile screen, I wrote 12 static analysis checks that read the layout XML and activity Kotlin source — catching the same categories of issues an Espresso test would (input length caps, debouncing, accessibility, button state during loading, unsaved-edit warnings, etc). Live UI tests can be re-run against this screen once we have a fresh test account or reset this one via backend.

7. Methodology

  • Voice Verification tests drive the running app through adb shell input commands and capture the UI state after each interaction using uiautomator dump. Every case captured before/after screenshots and a slice of logcat.
  • Test V-06 specifically verifies the 30-second auto-stop fix we shipped (hold mic 32s → expect auto-stop + Submit visible).
  • Edit Profile tests parse the layout XML and activity Kotlin source with deterministic regex checks. They look for: maxLength on inputs, inputType, accessibility contentDescription, button disabled-while-loading, text-watcher debouncing, prefs-on-scroll, unsaved-edit guard, HTML rendering of name, interest count cap, observer wiring.
  • Screenshots and logs are saved alongside the JSON results in QA_Reports/ui_automation/ and can be re-run anytime.
