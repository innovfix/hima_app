# Firebase Firestore Setup Guide

## 🔥 Quick Setup Checklist

Follow these steps in Firebase Console to enable Firestore for your app.

---

## Step 1: Enable Firestore Database

1. Go to [Firebase Console](https://console.firebase.google.com)
2. Select your project (should already exist since you have Analytics/Crashlytics)
3. Click **Firestore Database** in the left menu
4. Click **Create database**
5. Choose:
   - **Start in test mode** (for initial testing)
   - **Location**: Choose closest to your users (e.g., asia-south1 for India)
6. Click **Enable**

---

## Step 2: Set Security Rules (After Testing)

### For Testing (Temporary - 30 days)
```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /{document=**} {
      allow read, write: if request.time < timestamp.date(2025, 11, 8);
    }
  }
}
```

### For Production (Recommended)
```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /chats/{threadId}/messages/{messageId} {
      // Anyone can read messages in their thread
      allow read: if true;
      
      // Anyone can write messages
      allow create: if request.resource.data.from != null &&
                       request.resource.data.to != null &&
                       request.resource.data.text is string &&
                       request.resource.data.timestamp != null;
    }
  }
}
```

**Note**: Since you're using your own authentication (not Firebase Auth), we use simpler rules. You can make them more secure by:
1. Adding a server-side Cloud Function to validate user tokens
2. Using Firebase Custom Tokens generated by your backend

---

## Step 3: Create Index (If Needed)

The app uses `orderBy("timestamp")` which may require an index.

### Automatic Creation (Recommended)
1. Run the app and send a message
2. Check Logcat for error like: "Index required: [link]"
3. Click the link to auto-create the index
4. Wait 1-2 minutes for it to build

### Manual Creation
1. Go to Firebase Console > Firestore Database > Indexes
2. Click **Create Index**
3. Collection ID: `messages`
4. Fields:
   - `timestamp` - Ascending
5. Click **Create**

---

## Step 4: Verify google-services.json

Make sure you have the latest `google-services.json`:

1. Go to Firebase Console > Project Settings > General
2. Scroll to "Your apps"
3. Click on your Android app
4. Download `google-services.json`
5. Replace the file in: `app/google-services.json`
6. Sync Gradle

---

## Step 5: Test Firestore Connection

### View Data in Console
1. Go to Firebase Console > Firestore Database > Data
2. After sending messages, you should see:
   ```
   chats
     └── 123_456
         └── messages
             └── [auto-generated-id]
                 ├── from: "123"
                 ├── to: "456"
                 ├── text: "Hello!"
                 └── timestamp: [timestamp]
   ```

### Check Logcat
Look for these logs after sending a message:
```
D/ChatActivity: MyUserId: 123, PeerUserId: 456, ThreadId: 123_456
D/ChatActivity: Message sent: [documentId]
D/ChatActivity: Loaded 1 messages
```

## 🚨 Common Issues

### Issue: "Cloud Firestore API has not been used"
**Solution**: 
1. Go to Firebase Console > Firestore Database
2. Click "Create database" to enable the API

### Issue: "PERMISSION_DENIED"
**Solution**:
1. Check Firestore Rules tab
2. Use test mode rules temporarily
3. Verify rules allow read/write

### Issue: "Missing or insufficient permissions"
**Solution**:
1. Update security rules to allow public read/write for testing
2. Later, add proper authentication checks

### Issue: Messages not syncing
**Solution**:
1. Check internet connection
2. Verify Firestore is enabled
3. Check Logcat for errors
4. Verify user IDs are valid (not -1 or empty)

## 📊 Monitor Usage

### Check Usage Stats
1. Go to Firebase Console > Firestore Database > Usage
2. Monitor:
   - Document reads
   - Document writes
   - Document deletes
   - Storage size

### Set Budget Alerts
1. Go to Firebase Console > Usage and billing
2. Set up budget alerts to avoid surprises
3. Recommended: Set alert at $10, $25, $50

## 💡 Best Practices

### 1. Paginate Messages
For conversations with many messages, load only recent ones:
```kotlin
.orderBy("timestamp", Query.Direction.DESCENDING)
.limit(50) // Load last 50 messages
```

### 2. Clean Up Old Messages (Optional)
Use Cloud Functions to delete messages older than 30 days:
```javascript
// Cloud Function (Node.js)
exports.cleanOldMessages = functions.pubsub
  .schedule('every 24 hours')
  .onRun(async (context) => {
    const cutoff = new Date();
    cutoff.setDate(cutoff.getDate() - 30);
    
    // Delete messages older than 30 days
  });
```

### 3. Compress Images Before Upload
If adding image sharing, compress images to save storage costs.

### 4. Use Batched Writes for Multiple Operations
```kotlin
val batch = db.batch()
batch.set(messageRef, messageData)
batch.update(threadRef, "lastMessage", messageText)
batch.commit()
```
